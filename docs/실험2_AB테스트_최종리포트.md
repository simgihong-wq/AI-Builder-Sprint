# 🧪 실험 ② 최종 리포트 — 정보 구조화 A/B 테스트

> 약속지킴이 (Promise Companion) · 팀 디티의꽃
> A안: Upstage Information Extract (Studio 에이전트, Parse→Extract, 스키마 10필드)
> B안: Solar Pro 3 프롬프팅 (동일 스키마, 콘솔 Chat)
> **최종 판정: 역할 분담 확정 — Extract는 "수집", Solar는 "판단". 직렬 파이프라인으로 서로의 구멍을 상쇄**

---

## 1. 실험 설계

- 입력: 실험 ①에서 검증된 실제 캡처 (당근·번개·문자, 협상/리스크/null 함정 포함)
- 스키마 10필드: item, final_price, location, datetime, delivery_method, payment_method, accessories, refund_policy, condition_info, risk_signals
- 핵심 함정 3종: ①협상 최종가(SSD 6만→5.5→5.8 합의) ②가격 충돌(게시 31만 vs 카드 15만) ③은근한 리스크("급전이 필요해서")

## 2. 결과 요약

| 평가 항목 | A안 Extract | B안 Solar |
|---|---|---|
| 협상 최종가 (58,000원) | ✅ 정답 | ✅ 정답 |
| 시스템 메시지 결합 (날짜·안전결제·택배) | ✅ | ✅ (당근페이 과잉추출 🔶) |
| null 처리 / 환각 억제 | ✅ | ✅ (다소 과잉신중) |
| 리스크 포착 — 노골 (선입금·계좌·대면거부) | ✅ 4/4 | 미테스트 |
| 리스크 포착 — 은근 ("급전이 필요해서") | ✅ | ✅ |
| 리스크 포착 — 이체 유도 ("이체랑 페이 뭐가") | ✅ | ❌ 누락 |
| **값 충돌 감지** (31만 vs 15만) | ❌ 침묵하고 한 값 선택 | ✅ **notes로 정확히 감지** |
| **언급 vs 합의 구분** (가야동=자기 위치 언급) | 🔶 location에 오기입 | ✅ null + "합의 불분명" |
| 멀티 캡처 필요성 | 협상 미포함 캡처에선 60,000원 → 대화 전체 커버 필수 확인 | 동일 |

## 3. 판정: "수집가 vs 판사"

- **Extract = 수집가**: 이미지에서 값·위험 발언을 빠짐없이 긁어모음. 단, 값들의 정합성·합의 여부는 판단하지 않음
- **Solar = 판사**: 충돌 감지, 합의/언급 구분 등 판단에 강함. 단, 수집 누락 발생(이체 유도 miss)
- → 어느 한쪽 단독은 구멍 존재. **직렬 배치 시 상호 보완 완성**

## 4. 확정 파이프라인 (최종)

```
카톡/당근/번개/문자 캡처 (여러 장 지원 — 대화 전체 커버 필수)
 → ⓪ 개인정보 마스킹 (전화·계좌·동호수 정규식) ★실측 근거: 계좌번호·아파트 동호수 완벽 추출됨
 → ① Document Parse (텍스트+좌표 → 화자 분리, 실험 ① 규칙)
 → ② Information Extract (수집: 10필드 값 + 위험 발언 후보)
 → ③ 코드 검증 (필수 필드 누락 체크 — 결정론적)
 → ④ Solar Pro 3 (판단: 값 충돌 감지 · 합의/언급 구분 · 리스크 의미 해석 · 확인 질문 생성)
 → ⑤ 약속 카드 (문구 다듬기: solar-mini)
```

각 단계의 존재 이유가 전부 실측으로 입증됨:
- ⓪: 실험 중 실제 계좌번호·동호수 추출 → 마스킹은 장식이 아닌 필수
- ②: 협상 최종가·시스템 정보 결합·리스크 수집 성능 입증
- ③: Extract가 충돌에 침묵 → 코드/Solar 검증 없이는 오답 카드 발급 위험
- ④: Solar만이 충돌 감지·합의 판단 가능함을 B안 실험으로 확인

## 5. 서비스 설계 반영 사항

1. **멀티 캡처 통합이 필수 기능** — 단일 캡처는 그 장면의 정보만 담음. UX: "가격·조건이 오간 부분을 모두 캡처해주세요"
2. **Solar 프롬프트에 반드시 포함할 지시** (B안 실측 기반):
   - "값들이 서로 충돌하면 반드시 지적하라" (notes 방식 검증됨)
   - "한쪽이 언급만 한 것과 양측이 합의한 것을 구분하라"
   - 리스크 예시 목록은 Extract가 이미 수집하므로 Solar는 "왜 위험한지 + 어떻게 확인할지"에 집중
3. **가격 충돌 = 리스크 신호로 승격** — 게시가와 상세가 불일치는 수수료 회피·사기 수법일 수 있음 → 약속 카드에 "⚠ 가격 정보가 일치하지 않습니다" 표시
4. **데모 샘플 확정 후보**: SSD(협상 성공 스토리) / 아이패드 라이트(급전 리스크) / 티켓(이체 유도 + 가격 충돌) — 단, 계좌번호·동호수 등 실개인정보 포함 캡처는 가짜 정보로 재제작 후 사용

## 6. 발표용 문장

> "저희는 두 API를 감으로 고르지 않았습니다. 동일 스키마·동일 샘플로 비교 실험한 결과,
> Extract는 수집에, Solar는 판단에 강하다는 것을 확인했고,
> 그래서 파이프라인에서 Extract가 모으고 Solar가 판단합니다.
> 이 아키텍처의 모든 단계는 실측 데이터로 존재 이유가 증명되어 있습니다."
