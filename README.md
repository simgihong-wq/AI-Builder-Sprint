# 🌸 약속지킴이 (Promise Companion) — 팀 디티의꽃

> AI Builder Sprint 2026 · 중고거래 채팅에서 빠진 약속과 분쟁 리스크를 찾아주는 분쟁 예방 서비스
> **"문서가 아니라 신뢰를 만드는 생활형 CLM"**

## 서비스 소개

당근마켓·번개장터·문자(iMessage)로 거래하다 보면 "얼마에 합의했더라", "환불은 된다고 했나"처럼
말로만 오간 조건이 뒤늦게 분쟁으로 번지는 경우가 많습니다. **약속지킴이**는 거래 채팅 캡처(또는
텍스트)를 넣으면 AI가:

1. 양측이 **실제로 합의한 조건**만 정리하고 (한쪽이 언급만 한 것과 구분)
2. **빠진 조건**과 **위험 신호**(가격 충돌, 재촉·급전 요구 등)를 찾아내고
3. 사용자 말투 그대로 **확인 질문**을 만들어주고
4. 양측 확인 후 공유 가능한 **약속 카드**를 발급

해주는 분쟁 예방 서비스입니다.

## 문제 정의

- 중고거래 분쟁의 상당수는 사기가 아니라 **"말로만 합의하고 기록이 없어서"** 생깁니다.
- 채팅을 처음부터 끝까지 다시 읽으며 뭐가 확정됐고 뭐가 안 됐는지 스스로 정리하는 건 번거롭고,
  바로 그 번거로움 때문에 놓친 조건이 분쟁으로 이어집니다.
- 계약서를 쓰자는 게 아니라, **이미 하고 있는 채팅에서 자동으로 신뢰의 근거를 뽑아주는 것**이
  더 현실적인 해법이라고 판단해 이 서비스를 설계했습니다.

## 아키텍처

```
캡처(다중) → ⓪ 마스킹(전화·계좌·주소 정규식)
           → ① Document Parse (텍스트+좌표)
           → ② 후처리·화자 분리 (y좌표 재정렬 → 타임스탬프 제거 → 노이즈 제거 → 화자 배정)
           → ③ 정보 수집 (Solar Pro 3 — 10필드)
           → ④ 코드 검증 (필수 필드 누락·가격 충돌 감지)
           → ⑤ Solar Pro 3 (충돌·합의 판단, 리스크 해석, 확인 질문·체크리스트 생성)
           → ⑥ 약속 카드
```

- Upstage 2종 API(Document Parse · Solar Chat Completions)가 핵심 경로 — 하나라도 빼면 서비스가
  동작하지 않습니다. 수집(③)·판단(⑤) 두 단계 모두 Solar Chat Completions를 호출하되, 프롬프트와
  호출은 분리해 실험②에서 확정한 "수집가 vs 판사" 역할 분담을 그대로 유지합니다.
  > ※ 원래 계획은 Parse·Extract·Solar 3종이었으나, 구현 중 Upstage Information Extraction API가
  > 텍스트(마스킹된 대화록) 입력을 지원하지 않고 image_url만 받는 것을 실측으로 확인했습니다.
  > 마스킹은 텍스트 단계에서만 가능해 원본 이미지를 Extract에 별도로 보낼 수 없으므로, 수집
  > 단계도 실험②에서 이미 검증된 B안(Solar Pro 3 프롬프팅)으로 대체했습니다.
- 판단(⑤) 단계는 프롬프트 지시만으로 끝내지 않고, **코드 백스톱**을 같이 둡니다 — 대화가 길고
  지저분해지면 Solar 혼자 판단이 놓치는 항목(예: 환불 조건 미확인)이 실측으로 확인되어,
  `missing_items`·`checklistItems` 모두 코드 레벨에서 강제로 채워 넣습니다
  (`backend/pipeline/judge.py`의 `_merge_missing_items` / `_ensure_refund_checklist_item`).
- 품목별(전자기기 등) 분쟁 리스크 20종 데이터(`docs/dispute-rules.md`)를 판단 단계 프롬프트에
  동적으로 주입해, 품목에 맞는 체크 포인트(배터리 성능, 침수/수리 이력 등)를 추가로 훑습니다.
- 에이전트·RAG·LangChain 등 프레임워크 미사용 — 바닐라 Python + API 호출. 단순함의 원칙에 따른
  의도적 설계 결정입니다.
- 모든 설계는 구현 전 사전 실험으로 검증됨 →
  [실험① 화자 분리 검증 리포트](docs/실험1_화자분리_검증리포트.md) ·
  [실험② A/B 테스트 최종 리포트](docs/실험2_AB테스트_최종리포트.md)

## 로컬 기동 가이드

처음 클론한 상태에서 아래 순서 그대로 따라 하면 됩니다. **터미널 2개**(백엔드용 1개, 프론트엔드용
1개)를 열어서 각각 켜두세요.

### 실행 환경

| 항목        | 버전 / 값                                      |
| ----------- | ---------------------------------------------- |
| OS          | Windows 11 (Windows/macOS/Linux 어디서든 동작) |
| Python      | 3.11 이상 권장 (개발 환경: 3.14.3)             |
| Node.js     | 20 이상 권장 (개발 환경: 24.14.1, npm 11.11.0) |
| 백엔드 포트 | `5000` (Flask, `PORT` 환경변수로 변경 가능)    |
| 프론트 포트 | `5173` (Vite 기본 포트)                        |

### 1) 백엔드 (Flask API, `backend/`)

```bash
cd backend

# 가상환경 생성 (최초 1회, 선택이지만 권장)
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # macOS/Linux

# 의존성 설치 (최초 1회)
pip install -r requirements.txt

# 환경변수 파일 생성 (최초 1회) — 아래 "환경변수" 절 참고
cp .env.example .env
# .env 파일을 열어 UPSTAGE_API_KEY=up_본인키 로 채워넣기

# 서버 실행
python app.py
```

- 정상 기동 확인: 브라우저나 curl로 `http://localhost:5000/health` 접속 →
  `{"ok": true, "data": {"status": "up", "upstage_key_set": true}}` 이면 정상.
  `upstage_key_set`이 `false`면 `.env`에 키가 안 들어간 것입니다.

### 2) 프론트엔드 (React + Vite, `frontend/`)

새 터미널을 열고:

```bash
cd frontend

# 의존성 설치 (최초 1회)
npm install

# 환경변수 파일 생성 (최초 1회) — 백엔드가 이미 5000번에 떠 있어야 함
cp .env.example .env

# 개발 서버 실행
npm run dev -- --port 5173
```

- 브라우저에서 `http://localhost:5173` 접속.
- `frontend/.env`의 `VITE_USE_MOCK=false`이면 실제 백엔드(`VITE_API_BASE_URL`)를 호출합니다.
  백엔드 없이 화면 흐름만 보고 싶다면 `VITE_USE_MOCK=true`로 바꾸면 목업 데이터로 동작합니다.
- 백엔드 포트를 바꿨다면 `frontend/.env`의 `VITE_API_BASE_URL`도 같이 맞춰주세요.

### (선택) 파이프라인 자체 테스트

백엔드만 따로 검증하고 싶다면(프론트 없이):

```bash
cd backend
python tests/test_offline.py                              # 오프라인 단위 테스트 (API 호출 없음)
python tests/smoke_live.py tests/fixtures/ipad_chat.txt --judge   # 실제 Upstage API로 전체 파이프라인 1회 관통
```

## 환경변수

### `backend/.env` (← `backend/.env.example` 복사)

| 키                | 필수 | 발급처                                                                  | 설명                                          |
| ----------------- | :--: | ----------------------------------------------------------------------- | --------------------------------------------- |
| `UPSTAGE_API_KEY` |  ✅  | [Upstage Console](https://console.upstage.ai/) → API Keys 메뉴에서 발급 | Document Parse·Solar Chat Completions 공용 키 |
| `PORT`            |  ❌  | —                                                                       | 백엔드 포트 변경 (기본 5000)                  |

### `frontend/.env` (← `frontend/.env.example` 복사)

| 키                  | 필수 | 설명                                                          |
| ------------------- | :--: | ------------------------------------------------------------- |
| `VITE_API_BASE_URL` |  ✅  | 백엔드 주소 (기본 `http://localhost:5000`)                    |
| `VITE_USE_MOCK`     |  ✅  | `true`면 백엔드 없이 목업 데이터로 화면만 확인 (기본 `false`) |

`.env`는 `.gitignore`에 포함되어 커밋되지 않습니다. API 키를 코드에 하드코딩하거나 커밋하지 마세요.

## 시연 시나리오 재현 방법

시연 영상은 **가격 협상 → 게시가와 최종 합의가 충돌 → 급전 요구(리스크 신호) → 환불 조건 미확인**
흐름을 보여주는 아이패드 거래 대화로 진행했습니다. 아래 방법 중 하나로 동일한 결과를 그대로
재현할 수 있습니다.

> 참고: `AGENTS.md`에는 실제 캡처 샘플을 `test-data/`에 두기로 되어 있으나, 현재 스냅샷에는 아직
> 커밋되지 않았습니다. 지금 재현 가능한 자산은 아래 파일들입니다.

**방법 A — 제출용 독립 데모 페이지로 재현 (심사용 원클릭, 권장)**

`result/` 폴더는 `frontend/`를 전혀 건드리지 않고 디자인만 복사해 만든 독립 페이지라, 프론트엔드
설치 없이 백엔드만 켜면 바로 심사할 수 있습니다.

1. `result/실행.bat`을 더블클릭한다 (원클릭 실행). 백엔드 서버가 새 창으로 뜨고, 몇 초 뒤 자동으로
   `result/index.html`이 열립니다.
   - `.venv`·`.env`가 `backend/`에 아직 없다면(최초 1회) 위 "로컬 기동 가이드 → 1) 백엔드" 순서를
     먼저 따라 준비해두세요.
   - 원클릭이 안 되면 `backend`에서 `python app.py`로 서버만 켜고 `result/index.html`을 직접
     더블클릭해도 됩니다. 백엔드 주소는 `http://127.0.0.1:5000`으로 코드에 고정되어 있습니다
     (Windows에서 `localhost`가 IPv6로 먼저 풀려 타임아웃 나는 문제를 실측으로 확인해 고정한
     값입니다. 포트를 바꿨다면 `result/index.html`의 `#api-base` 기본값을 직접 고치세요).
2. "캡처 올리기" 탭에서 `result/test-file/` 폴더의 `1.png` ~ `5.png` **다섯 장 전부**를 한 번에
   끌어다 놓고 "분석 시작하기" (시연 영상과 동일한 시나리오를 재구성한 가짜 대화 캡처 5장).
3. 결과 요약 → 확인 체크리스트 → 약속 카드 순서로 넘어가는지 확인.
   (가격 충돌 31만↔37만원, "급전이 필요해서" 리스크 신호, 환불 조건 미확인 체크리스트가 떠야 정상)

**방법 B — 실제 프론트엔드에서 텍스트로 재현**

1. 위 "로컬 기동 가이드"대로 백엔드 + 프론트엔드를 모두 켠다.
2. `http://localhost:5173` 접속 → "텍스트 붙여넣기" 탭 선택.
3. `backend/tests/fixtures/ipad_chat.txt` 파일 내용을 통째로 복사해서 붙여넣고 "분석 시작하기".
4. 방법 A와 동일한 결과 흐름을 확인.

## AI 활용 증빙

이 프로젝트는 기획부터 구현·검증까지 Claude Code를 팀 공통 개발 도구로 사용했습니다.

- **[AGENTS.md](AGENTS.md)** — 팀 공통 규칙의 단일 진실 소스. 아키텍처·화자 분리 규칙·데이터
  스키마·Solar 프롬프트 필수 지시·폴더 소유권(충돌 방지)까지 AI 에이전트가 그대로 따르는 실행
  가능한 규칙으로 문서화했습니다. `CLAUDE.md`가 이를 임포트해 Claude Code 전용 지침을 덧붙입니다.
- **[.claude/settings.json](.claude/settings.json)** — Hooks 설정. `PreToolUse` 훅으로 AI가 `.env`나
  `*.key` 파일을 수정/생성하지 못하도록 코드 레벨에서 차단하고(API 키 커밋 사고 방지),
  `PostToolUse` 훅으로 파일 수정 후 Prettier 자동 포맷을 강제합니다.
- **사전 실험 리포트** (대회 시작 전, 코딩 없이 가설부터 실측 검증) —
  [실험① 화자 분리 검증](docs/실험1_화자분리_검증리포트.md),
  [실험② 정보 구조화 A/B 테스트](docs/실험2_AB테스트_최종리포트.md).
  두 실험 모두 결론이 그대로 `AGENTS.md`의 아키텍처·화자 분리 규칙으로 확정되어 실제 구현에
  반영됐습니다.
- **AI 활용 로그** — 날짜·담당·작업 내용·핵심 기법·증빙 링크·절감 시간을 담당자별로 아래에 기록.

평가 기준 "AI를 통한 생산성 개선"의 근거 기록. 매일 각자 한 줄씩. (시간 절감 추정 포함)
